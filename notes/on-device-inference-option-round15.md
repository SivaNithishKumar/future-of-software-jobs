## Finding

The tractable specialism is lifecycle engineering: a model, tokenizer, cache, runtime/backend and task contract that continue to agree across memory pressure, cancellation, missing assets and updates. Small weight files or fast token generation are insufficient acceptance criteria. Native SDKs already bundle structured generation, cache control, model routing and evaluation, so a generic local-chat wrapper has a strong competitor.

The conditional 2031 opportunity is maintained native/runtime integration and task-specific failure diagnosis where platforms leave a measurable gap. Nothing here establishes job scarcity, future vacancy counts, a privacy guarantee or that the reader owns a compatible chip.

## Primary artifact 1: MLX-LM's state and compatibility boundary

Checked main **c39139d70f0798834fc721c28a1aa8e1374ea33c** is a source snapshot, not an installed/release-qualified environment. [MLX-LM](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/README.md) targets Apple silicon. Its [loader](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/utils.py#L265-L305) accepts a local directory or Hub ID; a nonexistent local-looking path enters snapshot_download. [load](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/utils.py#L648-L700) calls that helper. Thus the proposed offline adapter must reject absent local artifacts before invoking this route; a demo's model string is not evidence that no network fetch occurs. This is model acquisition, not evidence of a cloud-generation fallback.

Weights, active KV state and peak working memory are separate. [make_prompt_cache](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/models/cache.py#L15-L40) delegates to model.make_cache when present; otherwise max_kv_size creates a rotating cache. A model-specific cache can consequently have a different policy than a generic flag suggests. [maybe_quantize_kv_cache](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/generate.py#L305-L352) calls to_quantized once a cache's offset reaches the selected threshold. At this pin, [RotatingKVCache.to_quantized](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/models/cache.py#L540-L554) explicitly raises NotImplementedError. This establishes a conditional incompatible path, not that every model/cache rejects quantization or that a live run here failed. “Rotate and quantize KV” is not a universally composable memory recipe.

[KV allocation](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/models/cache.py#L251-L284) includes packed values plus group metadata, and its normal cache expands in 256-token steps. Nominal bits per value are not total runtime bytes. The [README](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/README.md#L199-L214) already explains that rotating context can trade quality for RAM and prefill step size trades peak memory for processing speed. A shorter cache must be assessed as a changed information policy.

Existing compatibility checks deserve credit: [cached-prompt loading](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/generate.py#L2039-L2080) rejects mismatched quantization bits/group size and a different supplied model identifier. This is stronger than no identity check. The inspected code does not establish that a reused path/ID whose contents changed is cryptographically tied to the original weights, tokenizer, adapter, template and runtime. The experiment adds immutable manifest identity around existing controls; it does not claim those checks absent.

[Generation statistics](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/generate.py#L700-L770) encode text before their prompt timer, expose separate prompt/generation rates and use MLX's peak-memory counter. They are useful native measurements, not full application load-to-accepted-output or a complete process/system memory ledger. The [native benchmark](https://github.com/ml-explore/mlx-lm/blob/c39139d70f0798834fc721c28a1aa8e1374ea33c/mlx_lm/benchmark.py#L117-L168) deliberately generates random token prompts, disables EOS stopping and warms before measured trials; it also reports a total-time field. This controlled throughput path is not a meaningful-document quality evaluation. Reuse it for its intended boundary and add the task trace.

## Primary artifact 2: llama.cpp already supplies useful controls

Checked master **1b29621bacc6a446bd523fc790316a24a06e886f** provides [CPU, Metal, CUDA, Vulkan and other backends](https://github.com/ggml-org/llama.cpp/blob/1b29621bacc6a446bd523fc790316a24a06e886f/README.md#L61-L96). Those are support declarations; they do not guarantee every model, quantization, cache dtype or operator works on every backend. The [model documentation](https://github.com/ggml-org/llama.cpp/blob/1b29621bacc6a446bd523fc790316a24a06e886f/docs/models.md#L1-L25) requires a compatible GGUF; a container conversion alone is not reference-output validation. Both runtimes have selected Qwen3 implementation source, but no converted checkpoint was loaded or compared here.

The [server options](https://github.com/ggml-org/llama.cpp/blob/1b29621bacc6a446bd523fc790316a24a06e886f/tools/server/README.md#L89-L111) include automatic memory fitting, an explicit model file and cache-only offline mode. Pin the effective configuration after fitting: a successful load with changed context/offload parameters is not a matched benchmark. Its [download implementation](https://github.com/ggml-org/llama.cpp/blob/1b29621bacc6a446bd523fc790316a24a06e886f/common/download.cpp#L452-L470) skips its online path in offline mode and fails if a required cached file is absent; its Hub planner also uses cached file metadata without online listing. This strengthens offline acquisition support. It does not certify all networking from a wrapper, tools, RPC backend, update mechanism or operating system.

[Server cache/slot settings](https://github.com/ggml-org/llama.cpp/blob/1b29621bacc6a446bd523fc790316a24a06e886f/tools/server/README.md#L163-L178) make concurrency, shared KV, checkpointing, prompt cache RAM and warmup explicit. They are not absent problems requiring a new server. Default listener is loopback and built-in tools are disabled; enabling tools, remote backends or a wider listener creates a different experiment. Keep the proposed task read-only with no file/tool execution.

[llama-bench](https://github.com/ggml-org/llama.cpp/blob/1b29621bacc6a446bd523fc790316a24a06e886f/tools/llama-bench/README.md#L85-L101) separates prompt, generation and combined tests, repeats them and can vary context depth. Its documentation explicitly excludes tokenization and sampling time. Token rate cannot be substituted for end-to-end correct-task latency, and short isolated runs do not demonstrate sustained thermal/battery behavior.

## Primary artifact 3: native Apple model routes and measurement

The [current Foundation Models landing page](https://developer.apple.com/foundation-models-framework/) describes on-device, Private Cloud Compute and third-party server models under the same API. Its [WWDC26 source transcript](https://developer.apple.com/videos/play/wwdc2026/241/) describes explicit model/profile switching and context-inspection APIs. It also calls this a “2027 release” while discussing OS27 on a WWDC26 page. These are advertised API/documentation observations; selected SDK/OS availability and entitlements were not verified. Do not infer a silent fallback from the existence of multiple providers, or infer offline execution from the framework name.

Official indexed [SystemLanguageModel documentation](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel) describes availability checks and OS-associated model changes. [modelNotReady](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel/availability-swift.enum/unavailablereason/modelnotready) can reflect assets downloaded automatically according to network, battery and load. Direct page bodies require JavaScript here; those details are indexed-primary evidence. An offline inference test after provisioning is distinct from installing missing assets offline. [TN3193](https://developer.apple.com/documentation/Technotes/tn3193-managing-the-on-device-foundation-model-s-context-window), revision 31 March 2026, describes a 4096-token on-device session and token-count/context APIs. Keep that version boundary: instructions, schema, history and outputs consume budget; do not apply 4096 to every current or third-party model. Native context-size/token-count controls are preferable to a guessed characters-per-token constant.

The [official Power Profiler session](https://developer.apple.com/videos/play/wwdc2025/226/), especially 1:52/16:19, distinguishes system battery %/hour from subsystem power-impact scores and describes thermal/state/observer effects. Those quantities are not automatically watts or joules per task. A model's allocator counter, CPU utilization, battery percentage drop and a validated energy meter are different observations. No Apple privacy/performance claim was independently verified.

## Exact optional model metadata and rights

For a metadata-only example, Qwen/Qwen3-0.6B revision **c1899de289a04d12100db370d81485cdf75e47ca** has a pinned [configuration](https://huggingface.co/Qwen/Qwen3-0.6B/raw/c1899de289a04d12100db370d81485cdf75e47ca/config.json) and [Apache2 licence text](https://huggingface.co/Qwen/Qwen3-0.6B/raw/c1899de289a04d12100db370d81485cdf75e47ca/LICENSE). This is not a choice of best model or permission to download one. Its card advertises 32768 context; config.max_position_embeddings is 40960. Those are different metadata fields, not a demonstrated runtime limit. Record both and test the chosen bounded contract.

For a dense full-attention cache with batch 1, 28 layers, 8 KV heads, head dimension 128 and 2-byte K/V elements, the logical KV payload is 2×28×T×8×128×2 bytes: 112 KiB/token, 448 MiB at 4096 tokens and 3.5 GiB at 32768. This is own arithmetic using configuration fields, not observed memory. Padding, scales, allocation growth, activations, workspaces, resident weights, application/OS memory and backend copies are excluded; sliding/recurrent/hybrid models need different formulas. A toy 4-bit group of 64 plus two FP16 metadata scalars uses 4.5 nominal bits/value before other overhead. Do not claim exactly 4× total-memory savings from a 4-bit label.

MLX-LM and llama.cpp MIT texts were inspected at their pins; their licences do not license model weights, tokenizer/data or platform SDKs. The original checkpoint licence does not establish a third-party converted artifact's provenance, notices or fidelity. No weights, tokenizer package or external text dataset was downloaded. The task below uses owned synthetic records; public corpus evaluation would require its own rights/contamination audit. Apple SDK/model use has [platform terms](https://developer.apple.com/support/terms/acceptable-use-requirements-for-the-foundation-models-framework/), not an open-weight licence.

## One 30/90-day experiment: local-only compatibility and task trace

Proposed local-round15.project.offline-contract. The task is read-only extraction of an item identifier and integer quantity from small invented stock notes, with explicit “insufficient/contradictory” outcomes. No commands, real documents, sensitive media or commits. The independent oracle is structured source truth plus an independently reviewed semantic mapping; JSON validity is only a transport check. Include distractor items, corrected quantities, negation, duplicates, truncation and ambiguity.

**First 30–50 focused hours**, a planning assumption: contract/manifest (8–12), tiny owned reference/trace pack (8–12), independent failure/compatibility review (8–14), and evidence memo/baseline specification (6–12). No model or runtime is required. Implement only an adapter contract and owned trace replay in an already approved stack. Native structured-data parsing and a transparent finite grammar/slot parser are strong task baselines; if the parser suffices, retain that result rather than forcing an LLM. A trace says what happened in that trace, not how an absent model behaves.

The manifest identifies model/revision/file hashes, conversion command/version, per-tensor dtype/quantization scheme, tokenizer/vocabulary/template hash, adapter, runtime/backend/driver/OS, context cap, prefill/parallelism, cache class/bits/group/threshold/identity, stop/sampling policy and fallback/network policy. Missing artifacts remain unavailable, without dispatching a Hub ID/default downloader. A loaded file's existence is not a numerical or semantic compatibility certificate.

Propose 40 exposed development cases and 40 fresh cases specified by an independent setter before learner access, grouped by underlying note/template so paraphrases do not cross partitions. Known test answers in this report cannot become a blind holdout. If no setter is available, label an exposed regression exercise. A separate reviewer should include a mature parser versus model counterexample, rather than evaluating only examples chosen to make the model useful.

Inject owned trace states: missing assets; unsupported backend/dtype/cache combination; same path with changed artifact identity; stale cache; context overflow; cancellation before/after partial output; repeated request IDs; memory pressure; interrupted load; unavailable native model; and network denied. Acceptance is exact expected state transition, no post-cancel accepted answer, no stale partial output as a new success, and no dispatch to a network/model provider outside the declared policy. A recorder's self-reported “offline” field is not independent network evidence. Use an independent outbound-request observer or controlled network-denial witness only in the later approved device stage.

**Next 90–150 focused hours**, conditional on explicit approved runtime/device/weights access: reproduce native baseline and manifest (20–30); exact-checkpoint high-precision versus one quantization/cache change (25–40); task/latency/memory/network evaluation (25–45); independent replay and contribution review (20–35). No chip ownership or install authorization is assumed. Choose one supported CPU/native-device path; Apple-silicon MLX is only one branch. No purchase, account/gate acceptance, external generation or paid cloud is part of this pass.

There are two distinct comparisons. For quantization/cache effects, hold base checkpoint, tokenizer, template, prompt, decoding and runtime/device constant, changing one policy. For native-platform task utility, compare the selected model with an already available system model and the parser under the same task oracle; a different native model is a product baseline, not an isolation of quantization. Use mature native benchmark tools for their supported boundaries, never their defaults that would acquire unapproved models. Native OS SDKs also bundle guided generation and evaluations, so a custom schema wrapper is not a novel contribution.

Before device timing, set a target task envelope (for example input<=512 actual tokens, output<=64, batch1, declared context limit) and an agreed absolute memory ceiling with OS headroom. These are proposed choices and can change only with a new contract. Token counts must come from the actual tokenizer/native API. Compare exact fields and appropriate abstention separately from formatting, crash/unsupported rate and all-attempt acceptance. Let the independent setter reserve 30 answerable and 10 deliberately underdetermined/contradictory cases within the 40 fresh cases. Proposed task gates are at least 27/30 exact answerable outcomes and 9/10 correct abstentions, and no additional errors on cases the strong baseline answers correctly; report paired failures and uncertainty. This is a finite-pack engineering gate, not a powered statistical noninferiority claim. These small samples give weak rare-error bounds.

Proposed runtime gate is p95 request-to-validated-answer <=2 seconds for this tiny task, plus an agreed memory ceiling and zero observed undeclared outbound dispatch. This is a planning threshold, not a universal UX/safety/privacy standard. Include load/tokenization/prefill/decode/sampling/validation and cold/warm/cache-hit variants; partial first-token latency is separate. Queueing, retries, unavailability and failures remain in attempted-task counts. Record sustained repeated blocks with randomized/interleaved arm order, cooling/thermal and battery/charger/display/network state; measure observer overhead and do not call repetitions independent devices.

Report total measured energy over the declared attempted workload divided by accepted tasks only when a validated joule source/boundary exists. Otherwise retain native power-impact/%hour metrics in their own units and leave joules unmeasured. A toy 2 Wh budget over 50 attempts is 144 J per accepted task if all succeed, 180 J if only 40 succeed; no actual battery capacity, savings or service battery life follows. Package/device idle subtraction, charging and other-process activity need their own uncertainty; CPU activity is not an energy oracle.

Kill/redirect if the parser/native platform already meets task needs, a memory saving truncates necessary evidence, matching quality removes the latency/energy advantage, cold preparation dominates expected use, metadata/settings cannot be pinned, or offline behavior lacks an independent witness. With no approved runtime/model/device, finish the manifest/reference/replay artifact and explicitly leave model accuracy, operational isolation, memory and energy untested.
