# Genomics workflow software: reference, representation and benchmark scope — round 22

Checked 20 October 2026; owner /root/bio_science. Existing bio/molecular notes and the source index cover variant-effect models, not a reproducible small-variant comparison workflow. This pass fills that gap with one contract: **compare a germline small-variant VCF to the intended benchmark/reference and report exactly what was assessed**. It does not build a variant caller or interpret pathogenicity.

No patient/private data, genome/read files, models, software binaries, accounts or paid systems were accessed. Public code/specification/paper/job sources were read; no external software was installed/executed. A 12-base invented contig and eight exposed structured cases were authored; only tiny own string edits, coordinate checks and hashes ran. No Nextflow, Sarek, hap.py, vcfeval or clinical analysis ran. Earlier notes/tree/catalogues remain unchanged.

## Why this is a distinct software option

Reference identity, intervals, diploid representation, comparison policy and workflow provenance can alter an accuracy report before any new scientific model is involved. The attainable work is a narrow adapter/regression/report contribution that explains those changes and survives independent replay. It needs biological data semantics alongside ordinary software judgment. It does not universally require a biology PhD, and a short project does not remove a particular role's experience,degree,location or clinical responsibilities.

**Conditional 2031 inference:** maintained scientific workflow/runtime/QA ownership may remain useful as native tools improve. Thin pipeline launchers and generic VCF comparators face strong existing automation. No employment count, scarcity, clinical benefit or venture demand is estimated here.

Hansen and collaborators' **A complete diploid human genome benchmark for personalized genomics**, Cell189,4857–4875.e31,6August 2026, DOI[10.1016/j.cell.2026.06.016](https://pubmed.ncbi.nlm.nih.gov/42561913/), is a published version after the older NIST-page clock. Its headline completeness/accuracy comparisons were not independently method-audited or reproduced here. The current assembly README is not a substitute for the paper's exact method/data version.

Public benchmark genomes are selected materials, not representative patients. Reusing the same sample,or relatives from a trio, across tuning and evaluation does not produce an independent population holdout. Chromosome/region splits within one person address another question. Record caller/model training provenance where available,workflow tuning exposure, sample/family, library/platform and difficult-region coverage. Public truth can support regression testing while remaining exposed to developers.

## Mature comparison is the baseline, not a new invention

Krusche et al., **Best practices for benchmarking germline small-variant calls in human genomes**, Nature Biotechnology 37, 555–560, 11 March 2019 online / May issue, DOI[10.1038/s41587-019-0054-x](https://pmc.ncbi.nlm.nih.gov/articles/PMC6699627/), provides the relevant method. The inspected inputs include truth/query VCF, benchmark BED and reference FASTA. Matching distinguishes genotype,allele and local criteria; complex records can describe equal haplotypes. Normalization alone does not reconcile every compound representation. Unknown calls outside benchmark regions and no-call/counting policies affect interpretation. Its easier-region and sample limits remain material; the paper's historical coverage figures are not current v5.0q coverage claims.

[hap.py at 84011695…](https://github.com/Illumina/hap.py/blob/84011695b2ff2406c16a335106db6831fb67fdfe/README.md) already performs representation-aware comparison,stratification and counting; its README recommends vcfeval for some complex corner cases. [RTG Tools 3.13](https://github.com/RealTimeGenomics/rtg-tools/releases/tag/3.13), release 28 May 2025, resolves to f72c7991… and provides a native haplotype comparator. These are strong alternatives to writing another record-equality “accuracy” checker. RTG 3.13 requires Java 11+. hap.py's checked HEAD is not an installed/release-qualified environment; its README still contains older Python 2/build examples. Choose a tested compatible later environment rather than following stale install snippets.

The [hap.py guide](https://github.com/Illumina/hap.py/blob/84011695b2ff2406c16a335106db6831fb67fdfe/doc/happy.md) explicitly treats outside-region query calls as UNK and documents special insertion/region capture behavior. Passing only a narrowed subset to the comparator differs from retaining calls and classifying unassessed ones. A single headline precision/recall can improve when difficult regions disappear. Report assessed bases/intervals, truth/query counts,TP/FP/FN,UNK,no-calls,filter policy and strata, with the chosen engine/decomposition/genotype/phase definition. Preserve native truth-side versus query-side units rather than forcing complex-record counts into one universal event count. Undefined/zero-coverage metrics do not become 100% accuracy.

The [VCF specification](https://samtools.github.io/hts-specs/VCFv4.5.pdf) is VCF 4.5/BCF 2.2, 25 February 2026, printing e821e4f; the full source commit was resolved. The toy plan deliberately uses only simple VCF 4.2 semantics, supported by the [older version's specification](https://samtools.github.io/hts-specs/VCFv4.2.pdf): ordinary base positions are 1-based. [UCSC BED](https://genome.ucsc.edu/FAQ/FAQformat.html) uses 0-based starts and excluded ends. New 4.5 features are not assumed compatible with an older parser. Indel padding,phase and interval-boundary behavior need the selected native contract, not a blanket POS-only membership rule.

## Workflow reproducibility has existing controls and explicit limits

**nf-core/sarek 3.10.0**, exact commit8ccac7ad37b05dd792447763bf9671b719824587, is a mature caller/analysis workflow upstream of this comparison layer. Its [README](https://github.com/nf-core/sarek/blob/8ccac7ad37b05dd792447763bf9671b719824587/README.md) describes release CI/full-sized tests, including GIAB germline/NCBench comparisons. Those are maintainer-described tests, not runs or scientific acceptance performed here.

The [configuration](https://github.com/nf-core/sarek/blob/8ccac7ad37b05dd792447763bf9671b719824587/nextflow.config) declares Nextflow>=25.10.4 and pins several plugins, including nf-schema and nf-prov. Native schema validation,provenance,version reporting,testing and existing comparison tools should be inspected before a new wrapper. Some institution configurations default to mutable master URLs; an offline guard is present. Pin the effective configuration/assets,not only the main pipeline tag. Test profiles and normal pipeline commands can acquire code,containers,reference assets and datasets; no such command was run or authorized here.

At **Nextflow 25.10.4**, commit701c82c1035b5813d0cbcfe60fb83d209743934c, [cache documentation](https://github.com/nextflow-io/nextflow/blob/701c82c1035b5813d0cbcfe60fb83d209743934c/docs/cache-and-resume.md) lists task hash inputs and requires both cache metadata and outputs for reuse. The [cache directive](https://github.com/nextflow-io/nextflow/blob/701c82c1035b5813d0cbcfe60fb83d209743934c/docs/reference/process.md#L453-L479) distinguishes default file metadata from deep content hashing and lenient metadata. Native resumability is useful; it does not certify reference-build meaning or biological truth. A content-change/metadata-preservation scenario is a proposed test, not an observed Nextflow defect. Reading a trace or versions file is not a native restart/durability test.

Rights stay component-specific: Sarek MIT; Nextflow Apache2; hap.py core SimplifiedBSD with dependency exceptions; RTG Tools BSD2-Clause, actual licence texts read. Pipeline plugins,tools,containers,reference databases and redistributed data have separate terms. Assembly CC0 does not automatically establish GIAB v5.0q VCF/BED rights. No open redistribution licence for the HTS specification itself was established in this pass; link it rather than assigning a code licence to the document. Paper access is also separate from code/data rights.

## A small lawful proof: compare meaning and expose incompatible inputs

Project genomics22.project.variant-contract is proposed,not implemented as a native workflow. Its owned fixture pack embeds contig toyA22 = ACAAAAAGTCCG,not a participant genome. Five tiny own string/coordinate checks verify the authored illustrations; they are not a native VCF parser,benchmark or independent assessment.

The eight exposed seed cases cover equivalent homopolymer deletion encodings; one MNP versus two homozygous SNVs; same allele with a different diploid genotype; a phase-sensitive cis/trans distinction; same contig/name/length with changed reference bytes; a simple SNV's BED boundary; an explicitly counted no-call; and an empty benchmark mask. For example POS2 CA→C and POS3 AA→A produce the same homozygous toy haplotype,although the records differ. These are examples of known prior art,not a new normalization method. The phased example specifies a phase-sensitive window contract; it does not assert an unconfigured comparator's default behavior.

**First 30–50 focused hours**, assumed and gap-only: 8–12 contract/reference/version/rights reading;8–12 owned sequence/haplotype/interval oracle cases;8–14 provenance/status/report ledger;6–12 independent review/prior-art check. Required concepts are DNA/reference/allele and diploid genotype/phase,VCF/BED coordinates,missing/filter states and elementary precision/recall. Linux/Python,streaming data,testing and resource accounting transfer from ordinary software. Groovy/Nextflow is branch-specific; C++ is optional unless changing comparator/caller internals. No complete biology curriculum or PhD is a prerequisite for the metadata/toy exercise.

Retain exact FASTA/index/contig/sample/truth/BED/query hashes; benchmark/release,engine/flags/normalization/counting policies; container/plugin/config revisions; planned cases,failures and scope. The adapter should refuse mismatched references or missing benchmark contracts before producing an accuracy score. Preserve native reports and add only a justified missing join/check.

Use 40 development cases and a separately prepared 40-case fresh pack,grouped by underlying sequence/window rather than paraphrased records. Require an independent setter and reviewed expected haplotypes,interval membership and status/error tables before learner access. The examples here are exposed; if the learner authors/sees the key,call it regression practice. A proposed engineering gate is exact agreement on all supported fresh cases,explicit unsupported/unknown outcomes for every excluded case,and no incompatible input or zero-coverage case labelled a successful accuracy benchmark. It is not a population sensitivity/error-rate estimate.

**Next 90–150 focused hours**, conditional: 20–30 an approved tiny native comparator/environment baseline;25–40 changed representation/reference/region conditions;25–45 trace/report/cache-policy comparisons;20–35 independent replay and maintained contribution review. Setup has a 6-hour diagnostic subcap inside this allowance; without an approved compatible runtime or valid oracle,stop at the reference/metadata artifact. This does not stack onto every other specialty's budget.

The later native gate may use only the invented tiny FASTA/VCF/BED set with an exact compatible comparator and reference-index tooling. No full WGS,patient records or account is required for that limited software test. A full GIAB or Sarek calling campaign is a separate data/runtime/rights/compute decision,not implied by a test-profile name. The blocked v5.0q README means no claimed compatible GIAB benchmark is ready here. No performance,cache behavior or native parser acceptance has been measured.

Compare naive record equality only as a negative baseline; the meaningful comparator is the existing haplotype-aware tool and its exact policy. Separate benchmark contract failures,UNSUPPORTED,NOT_RUN,UNK,no-call and biological disagreement. Report setup/retry/validation/runtime/storage costs and grouped failures,not only successful tasks. No cost estimate for an entire genome is extrapolated from this toy.

Stop or redirect when native tooling already satisfies the contract; the project merely replicates known examples; rights/reference/expected-result joins remain unresolved; setup dominates; or the stronger claim needs real independent samples,domain review or representative workflow access. Original contribution needs a confirmed current upstream gap,an independently specified regression and maintainable change accepted on its merits. A toy manifest,green CI or a public GIAB score alone does not establish new science,clinical validity or paid demand.
