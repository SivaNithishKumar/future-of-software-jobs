## Compact protocol facts

The benchmark has701 task groups:150 shopping,270 travel,221 progressive search,40 math and20 physics; the latter two form one conceptual domain. Travel is derived from45 base itineraries. The paper reports4,850 subtasks. Memory starts empty per episode, carries action/observation information across dependent sessions, and is updated after subtasks. Long context, external memory and retrieval systems are compared. Shopping/travel success requires the whole final bundle/plan; search/reasoning success uses the final subtask. PS averages subtask success within tasks; sPS gives constraint-level credit. Search discards groups with causally unanswerable subqueries. Long context and BM25/embedding retrieval remain competitive; not every elaborate memory backend wins. A simulated oracle adds gold prior outcomes plus LLM-distilled workflows, rather than proving an optimal sufficient state. [v2 §§3–4, AppB/C.3](https://arxiv.org/html/2602.16313v2).

The repository explicitly calls itself a preview and exposes agent/environment/memory and setup entries. It requires separately available model/backend API configuration. The inspected page returned no immutable commit or explicit code/data licence grant. That is an unresolved release/rights join, not proof that no licence or runnable release exists elsewhere. [Official metadata/README](https://github.com/ZexueHe/MemoryArena).

## What the evaluation establishes—and leaves open

| Boundary | Method judgment |
|---|---|
| Task/session/user denominator | Count a grouped multi-session task separately from its questions, actions, subtasks or constraints.701 is not701 users, private conversations or months of memory.270 generated travel groups are not270 independently observed travellers. Related variants and source-paper chains require clustered uncertainty. |
| Human versus synthetic | Human crafting/verification improves the task oracle but does not create a recruited-user deployment study. Product chains and generated constraints are controlled constructions over existing environments; formal-reasoning labels involve expert-selected paper derivations. They are not new scientific discoveries. |
| Logical versus calendar time | Session order and persistent state within an episode test dependency, not months of retention or natural user drift. Clearing memory between episodes also differs from a shared, lifelong multi-user store. |
| Updates, contradictions, deletion | The study accumulates constraints and interaction-derived memory. It does not establish a correction/retraction/delete propagation, conflicting-authority, purpose-revocation or physical-erasure evaluation. Absence of such a reported test is not proof the compared products lack those features. |
| No-answer and forgetting | Removing causally unanswerable search groups makes a clean solvable-task benchmark; it does not measure safe abstention on missing evidence. Declining success with dependency depth mixes retention, retrieval, reasoning, planning and compounding earlier mistakes. It is not an isolated forgetting rate. |
| Recall versus useful action | This is stronger than static recall: earlier state can change later simulated decisions. But simulated purchases, itinerary constraint satisfaction, final answers and scientific reasoning are different action/oracle classes. None establishes real checkout authority, booking, money movement or permitted disclosure. |
| Success versus complete trace | Do not describe every SR as all subtasks passed: final-query/final-reasoning SR can differ from intermediate PS. Do not turn the all-track average into a pooled701-task count without the exact aggregation/attempt manifest. |
| Known context and oracle | Complete or gold-like context can still be used incorrectly. The gold-outcome/workflow injection supplies extra assistance, not just a more accurate retriever. The latent sufficient state and procedural knowledge are not independently certified; the arm cannot prove memory is the sole bottleneck. |
| Native/simple comparisons | Preserve ordinary long-context history, BM25 and embedding retrieval as serious alternatives. A persistent structured task ledger is also a proposed local baseline; it was not evaluated by this reading. A simple baseline winning is useful architecture evidence, not a failed project. |
| Compute and scaffold | Default memory retrieval is described as once per session, although the abstract loop permits action-level calls. Protocol budgets vary by environment; cap, timeout, context and memory-server configuration must be matched for a cost claim. The paper reports latency, not a complete build/write/index/store/model/failed-attempt/review bill. |
| Contamination and scoring | Historical public source tasks, papers and environment corpora do not establish training-exposure cleanliness. Expert reference answers are valuable, but the actual grader/held-out access implementation was not inspected. “Formal reasoning” here must not be sold as Lean/kernel-checked proof. |
| Privacy and authority | Correctly retrieving a historical preference says nothing by itself about current caller/tenant/purpose rights or an action's present preconditions. Neither the memory receipt nor a remembered permission substitutes for the authoritative access/commit check. |

The reported configuration also needs an exact model/version join: prose names GPT-5-mini while Table3 names GPT-5.1-mini. I did not normalize those aliases or adopt a current model ranking. The all-task average and approximate-oracle arms also need their actual case/configuration manifests before comparison. These are bounded reproduction limits, not an accusation of invalid results.

AppendixB supplies concrete protocol information: session-level retrieval, shopping output/round caps, search retrieval top5 with512-token document truncation, and separate reasoning generation settings. Model APIs and H100 use for GPU-requiring experiments are described. Temperature0 is a stated setting, not a guarantee of bitwise repeatability. Full failure/timeout/retry treatment, repeated-seed uncertainty, complete cost and paper-matched code/data/image identities were not established by the three endpoints. No expensive reproduction is authorized or claimed.

## Optional attachment to one existing artifact

It already proposes independent expected outcomes, adversarial scorer cases, held-out follow-up and matched budgets. The existing Q4/memory-adaptation plan and authority notes are context, not additional projects or hours. This new attachment is proposed, unapplied and not an assertion that the benchmark implements it.

Within one already selected scorer case family, add a **source-version/claim/time/presence report** for an owned synthetic document workflow. Before any actor exposure, an independent setter must freeze the expected claim, valid time, supersession rule, source and request/state permissions. If that setter or lawful runtime is unavailable, stop at an exposed schema/consistency diagnostic. Do not import private conversations or user profiles.

Keep three distinct envelopes:

- Evidence: claim/source IDs; exact source revision/hash and pointer; observed time and valid-time interval; supersession/retraction state; source scope; and value presence as absent, explicit-null, value or not-inspected. Unknown time/rights stays unknown rather than invented.
- Current decision: query-as-of time; relevant current caller/tenant/purpose context supplied by the authoritative test system; source/policy/state revisions actually checked; permitted/denied/indeterminate outcome; and its independent expected answer. A memory record is evidence, not a grant.
- Effect: intended operation ID, actual state/effect receipt and source revision at commit, or an explicit unrun/no-effect state. A correct answer and an accepted state transition are separately scored.

Select only a bounded replacement for existing scorer cases: a valid remembered fact that is now superseded; an absent fact versus explicit null; an unresolved contradiction or no-answer case; a deleted source whose derived summary must be withheld; a correct fact requested by the wrong synthetic caller; and a legitimate permitted completion. Include the positive completion so denying everything cannot win. Distinguish removing retrieval exposure from physical erasure or model unlearning; the latter are not established by a local report.

Compare an ordinary versioned structured store and configured native access/transaction path, long-context or lexical retrieval where already available, and at most the existing justified custom arm. Documentation or simulation does not become native execution. Future model use requires separately approved resources; this task runs none. Preserve all attempts, stale/forbidden exposures, wrong denials, inconclusive cases, repairs and actually measured cost/latency. No best-case query can stand in for the eligible request denominator.

Kill a custom-memory advantage if the ordinary baseline already meets the legitimate contract more simply; the independent oracle accepts a planted serious wrong effect; retrieval success hides stale authority; gains require extra uncounted context/construction; or a final holdout was used to tune the policy. A stronger future native/model policy that handles the same valid-time and authority cases at lower full cost would weaken the bespoke-memory preparation bet. Neither outcome establishes a durable moat, funded demand or future job count.
