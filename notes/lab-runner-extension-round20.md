# A new conditional extension for the laboratory runner

Research/design only,19October2026 UTC /20October India. The frozen `science-enrichment-round5.project.labrunner` authors a **30-day /30–50-hour** software proposal. Its reference to stronger evidence within90days is not an authored90-day implementation phase. This file proposes a new extension; it does not rewrite that source, alter the kernel, assert completed prerequisites or turn a simulator into a laboratory safety/assay oracle. No biological procedure, physical action or upstream program was executed.

The narrow question is: **can an external software controller preserve units, resource/version identity and honestly unknown execution state across a lost acknowledgement and restart, beyond the selected framework's existing checks?** One fixed synthetic resource workflow and one primary native framework are enough. A new agent framework, cross-vendor controller or self-driving laboratory is outside this proof.

## The proposed CPU contract

Use fictional resource IDs and a tiny synthetic event script; no samples, substances, assay records or private instrument logs. A plan manifest records its bytes/hash, command schema, normalized unit contract, resource-definition IDs/versions/hashes, initial declared state, SDK/API/backend/tracking configuration and controller/oracle versions. Keep wall-clock, monotonic timing and logical event order distinct. Every value identifies its origin: requested,declared,native-tracked,synthetically observed or unknown. No field is labelled physically measured.

Specify three distinct event meanings before code: an initial/replacement declaration; a modeled effect with a unique action ID; and an observation of that effect. A declaration update is not a transfer. Reserve synthetic resources against a plan/resource generation, and reject stale generation or incompatible units. Only commensurate modeled quantities may be conserved; this is no concentration, chemistry or material-composition model. Native adjusted values/warnings must survive alongside requests rather than being rounded away to make a checker pass.

The control states include planned,submitted,accepted,in-flight,unknown,confirmed-complete,confirmed-not-executed and blocked-for-review. Acceptance does not mean completion; timeout or cancellation acknowledgment does not mean an effect was absent. A result observed for another action/plan/resource generation cannot settle this action. A local transaction around an event store cannot make an external physical effect atomic.

The **independent synthetic oracle** is a separately specified expected state/effect ledger plus a fake read-only outcome observer. Its truth script decides whether an abstract effect occurred and can lose the response afterwards. The controller may consult only the declared observer interface; it cannot read the hidden truth flag directly or let an LLM invent the answer. If the observer supplies no authoritative action-linked result, preserve unknown and stop the dependent path. Retry only after proof of nonexecution or the exact idempotency contract of that backend; do not assume vendor hardware supports universal deduplication. No automatic physical compensation is proposed.

Baselines are:

- **B0:** the unmodified chosen native simulation/testing backend, with its real checks, warnings, tracking and snapshot features enabled as selected. Record what it checks and does not observe.
- **B1:** an ordinary deterministic controller, native validation and a minimal durable local event store using the same observer, units, permissions and retry policy. This is the serious orchestration baseline.
- **Candidate:** only a narrowly justified version/units/provenance or reconciliation correction. An optional model can propose typed plans later, with identical validators/effect authority and separately approved cost; it is unnecessary for the initial experiment.

A duplicated independent oracle can expose a mismatch, but does not automatically warrant a duplicated product layer. If B0/B1 already meets the contract more simply, report it and prepare a test/documentation candidate. PyLabRobot's saved-state/validation features are explicit rivals to a claim that a new wrapper invents reproducibility. Its stored-log validation tutorial begins from a real captured run; this plan does not fake that prerequisite or call synthetic capture a hardware reproduction. [Native stored-log scope](https://docs.pylabrobot.org/stable/user_guide/machine-agnostic-features/logging-and-validation/validation.html).

## Metrics, controls and rejection

Report every offered attempt,including blocked,unknown,incomplete and native-unsupported cases. Primary finite-suite gates are zero silently accepted critical unit/version/resource violations; zero duplicate modeled effects; no unknown promoted to complete; expected final logical state/status; and complete action/plan/resource/version/provenance linkage. Checkpoint/restore must retain unresolved actions and the exact selected state contract. A process restart is not a power-loss/durable-storage guarantee.

Seed missing unit normalization,stale generation acceptance,metadata-as-addition,duplicate-after-timeout,unknown-as-success and a missing ledger field. Valid baseline cases must still pass. Report disagreements by root cause,including native behavior that was already correct. Keep initial/changed-family denominators separate; a new random seed within one generator is not a new protocol family. Small deterministic fault injections are not measured incident frequency,operating reliability or safety certification.

Measure setup,debugging,review/repair and observed CPU/runtime/storage costs only when actually run. A synthetic observer's answer is not saved operator labor. Human workload benefit needs an authorized representative workflow and an observed human baseline; until then it is unknown. No later acceptance rate or commercial value is inferred from the source library,paid scientist roles or a larger case count.

Stop the stronger claim if no independent expected state/rights exists, native setup cannot be bounded, the result requires disabling baseline checks, or the observer cannot resolve ambiguous execution. Reject the new custom layer when a mature configuration is simpler or its gain disappears under equal information/cost. Retain source-only/software learning rather than interpreting access failure as inability. An actual native regression candidate still requires project-specific current tests,review and maintainer interest; there is no promised contribution acceptance.
